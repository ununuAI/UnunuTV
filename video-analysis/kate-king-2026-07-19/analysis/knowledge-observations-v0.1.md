# Knowledge Observations v0.1

Status: candidate observations only.

## Core Diagnosis

KATE KING 视频里可见的 Prompt 不是单纯故事版，也不是把剧本压缩成动作摘要。它更接近“参考资产＋生成单元内部的镜头/动作协议”：明确人物关系、空间、镜头序列、表演反应、摄影与结束状态，再让一个请求生成一个或多个艺术分镜。

这些视频能直接证明“展示者采用了这种写法”，不能单独证明某模型一定支持某能力、该写法一定优于其他写法，或展示结果未经筛选/后期。

## Repeated Patterns

1. 参考缩略图与 Prompt 同屏出现，参考资产顺序和角色职责是生成输入的一部分。
2. 多数长 Prompt 使用有序镜头/段落，而不是只写总体剧情。
3. 多镜头请求普遍包含建立镜头、关系镜头、物件/手部特写、人物反应和结尾状态。
4. 对白场景依靠说话者—听者反应—再回应的次序组织，表演不是一个抽象情绪词。
5. MV 和蒙太奇案例跨多个地点，但服装、道具、色彩、光线和关系状态仍承担连续性锚点。
6. 动作案例强调人物站位、武器/道具归属、方向与接触前后状态。
7. 类型片效果由黑白/综合色彩、动机光、雨地反射、物件插入镜头和构图共同形成，而非堆“电影级”。
8. 汇编视频把多个独立生成案例剪在一起，因此必须区分艺术场景、生成单元和展示视频。

## Workflow Patterns

```text
项目剧作事实
→ 选择人物/场景参考
→ 定义一个生成单元要包含的镜头或动作相位
→ 按有序镜头写动作、表演、摄影、灯光、声音和结束状态
→ 将模型参数放在独立请求层
→ 生成后审阅完整时间线
```

故事板图片可以帮助锁定多镜头构图或复杂动作，但这些视频本身也展示了直接使用人物参考＋多镜头 Prompt 的路线，因此不能把故事板设成所有任务的强制门禁。

## Product / Agent Implications

- `CinematicShotSpec` 必须保留剧作事实、动作链、表演微节拍、镜头运动目的、动机光和声音设计。
- `GenerationUnit` 必须允许关联一个或多个艺术镜头，也允许长镜头因 Provider 限制拆段。
- `ReferenceBinding` 必须用人物名和真实 Payload 顺序，不生成无来源“主体1”。
- `VisualAnchorPolicy` 必须按风险选择，允许 `NONE`。
- 专业 Agent 只回传结构化贡献，最终内容 Prompt 由单一编译器输出。
- Provider 参数、模型名、时长、比例、分辨率和数量必须与内容 Prompt 分离。
- 成片评估必须覆盖完整时间线，不能把请求成功当成通过。

## What Should Become Knowledge Cards Later

- 多镜头单次生成的镜头边界与切镜动机检查规则。
- 双人对白的说话者/听者反应顺序与“不得提前反应”规则。
- 参考资产职责、非职责和真实 Payload 编号规则。
- 类型片视觉效果的动机光、色彩、构图和信息释放组合方法。
- 动作相位、方向、接触、受力和道具归属检查规则。
- 汇编视频与单次生成结果的证据边界。

上述条目需与精确来源帧、外部模型能力注册表和内部生成测试结合后，才能从候选观察升级为正式规则。
