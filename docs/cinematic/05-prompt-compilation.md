# 视频 Prompt 编译协议

活动协议为：

```text
ununu.character.v2
ununu.image.v2
ununu.storyboard.v2
ununu.storyboard.keyframe.v1
ununu.video.single-shot.v2
ununu.video.multi-shot.v2
ununu.video.continuous-segment.v2
ununu.video.action-sequence.v2
```

前四个协议已经由正式编译器实现，不是只登记名字。图片协议详见 [02a-asset-authority-and-image-prompts.md](02a-asset-authority-and-image-prompts.md)。

## 单帧关键帧确定性顺序

参考富 Token 短映射 → 单帧任务纪律 → 视觉风格 → 唯一冻结时刻 → 空间关系 → 主体状态 → 摄影机/构图/景深/焦点 → 表演 → 光线/色彩 → 本帧连续性与禁止项。

每个字段独占一行。参考区固定使用 `参考图N「权威素材名」 = 本帧语义别名。`，不展开结构化职责长文。单帧 Prompt 不得含完整动作链、开场到结束演进、时长/时间槽、运镜路径、切镜、声轨、多个动作相位，或 node/media/capture/cameraSnapshot/revision/timestamp 等内部 lineage。`ununu.storyboard.keyframe.v1` 与任何 `ununu.video.*.v2` 分开编译、分开 lint，但由同一 Shot/VisualBible/Authority 合同派生。

超自然、异常解剖、物理例外和变形规则必须先拆成“两部分视觉合同”：明确哪些普通姿态或活动保持不变，再明确异常特征到底出现在哪里。躯干/肩线朝向、头部朝向、视线、手部与接触面分别记录，并把最容易生成的普通错误解释写入禁止项。例如“脸长在后脑”不能由肩膀和普通正脸一起转向镜头来满足；若付费前无法从字段中排除这种普通解释，单帧不得执行。

每张连续关键帧还必须做场景差分审计：与上一张已接受关键帧逐项核对桌、椅、酒杯、门窗、楼梯、柜台、群体占位、破坏痕迹和通路宽度。没有在本帧之前发生的明确可见因果，就不能让这些锚点消失、被打碎、整体移位或把狭窄空间改成空旷战斗场。动作需要通路时只能使用既有桌间缝隙或由已发生的爆破/撞击真实开辟，并把残骸和受力结果留在画面中。

每个有明确入口、目标或出口的关键帧还必须做“带符号的屏幕方向审计”：先锁定画面上的起点区、目标区和前进方向，再逐人检查髋肩、领先脚、视线、武器尖端、衣摆/速度线和 VFX 轨迹是否同向。若摄影机位于入口侧且主角应向远端推进，主角正脸/胸口却朝向摄影机奔跑，则视觉语义就是撤退，必须拒绝；入口与出口被镜像、人物与火轨反向、或任何主体方向无法一眼判定时也不得通过。

每个道具、投射物、接触特效和 VFX 还必须做“动作源因果链审计”：逐链检查“命名发起者 → 手/武器/接触点 → 道具或投射物 → 可见轨迹/冲击 → 目标”。轨迹的近端必须在空间上归属发起者，不得从摄影机脚下、画面边缘、另一角色或空处凭空出现。只有整体方向正确不够；任一连接缺失、断开、重复或归属错人都必须拒绝，并使下游 GenerationUnit 编译失效。

剧情中一旦完成怪物揭示、变形、受伤或服装/状态切换，后续关键帧还必须做“不可逆身份状态审计”。除非上一时刻已经出现明确可见的逆转因果，已揭示为尸傀/怪物的群体不得回复成普通活人。不仅要锁人数、服装和占位，还要按观看方向锁定异常解剖，例如“正面空白、完整鬼脸只在后脑”。任何无因逆变即使空间、方向和动作正确也必须拒绝。

## 视频确定性顺序

参考图映射 → 风格与场景布局 → 初始主体/空间状态 → 本段剧情与实际状态边界 → 续镜交接（若有）→ 有序镜头或动作时间线 → 调度/表演/摄影/焦点 → 灯光/色彩/物理/VFX/声音 → 连续性/结束状态 → 去重高风险禁止项。

`【本段剧情与实际状态边界】` 必须由 `GenerationUnit.sequenceState` 和 Core 的最新审片证据编译，明确真实入口、已发生不得重演、本段唯一任务、后续保留不得提前、四类导演意图承担项和目标出口。抽象 `feltIntent` 不直接发送；上一镜计划出口不能覆盖实际 ACCEPT 的 `carryForwardState`。

只输出有内容的段落。最终 Prompt 由单一编译器产生，专家不能各写一段后直接拼接。

## Lint 阻断

- 无来源“主体1/主体2”；
- 未绑定的 `[图片]`、`【照片】`、`image 1` 或不存在的参考图；
- `--ar`、`--v`、`--style` 等图片工具 CLI 参数；
- 内容 Prompt 中出现模型、时长、比例、分辨率、数量或音频开关；
- 参考图编号与 payload 顺序不一致；
- 锁定对白、剧情或关键动作丢失；
- 固定和移动机位在同一艺术镜头冲突；
- 单镜头协议中的显式或隐含偷切，多镜头协议无边界/切镜原因；
- 模型注册表不支持时仍输出内部绝对时间槽；
- 硬切错误使用上一镜真实尾帧；
- 图生视频逐镜状态载体没有绑定最新 media ACCEPT、当前 Shot revision、精确 checksum、像素审阅和五项跨模态状态域；
- `TAIL_CONTINUE` 与 `DUPLICATE_HANDOFF` 混用，或 H0/H1 不来自同一条最新仍为 ACCEPT 的上一段；
- 续段缺 H1、动作相位、摄影机方向/速度、焦段/焦点/曝光、声音桥、trim plan 或站位/道具/光线/动作相位/银幕方向五项守恒；
- 重叠交接在 H1 后没有明确新内容、重复区不可剪，或用固定秒数冒充实际动作相位切点；
- 未接受素材被声明为权威；
- 单帧关键帧缺少唯一冻结时刻，或泄露完整时间动作链和内部 Director/runtime 记录；
- 超自然/异常解剖规则只写故事结论，却没有拆分普通姿态、异常部位、视线与最易误解的禁止项；
- 连续关键帧未说明场景锚点的保留/改变原因，或在没有先行破坏动作时删除家具、群体与空间阻挡；
- 有明确空间轴却未锁定起点/目标/出口的画面区域，或人物髋肩、领先脚、视线、武器、运动轨迹与 VFX 轴反向/含糊；
- 道具/投射物/VFX 没有从命名发起者的手、武器或接触点连续延伸到目标，或轨迹近端错绑摄影机/画面边缘/另一主体/空处；
- 已揭示的怪物/尸傀/受伤/服装或其他身份状态在没有先行可见逆转因果时恢复普通状态，或观看方向与异常解剖对不上；
- 正式制作单元缺 `sequenceState`，已发生/本段/后续保留相互交叉，或下一镜没有从父单元最新 ACCEPT 的 observation/canon carry-forward 编译；
- 连续输出链超过单元配置的 `maxExtensionDepth`，或 `reanchor_after_drift` 没有重置深度并绑定已接受 Authority；
- 最终图片参考数超过模型注册表限制；GPT Image 2 第 6 张参考图必须在 Provider 能力预检前阻断；
- 不支持能力被当作生效；
- 重复矛盾禁止项或超字节上限。

以下项目默认给出警告并要求 Owner/专业审阅：绝对身份一致承诺、连续堆叠“电影级/大师级/顶级”等空泛词、直接模仿导演/艺术家/受保护 IP。编译器优先使用可解释的景别、透视、机位路线、动机光、综合色彩、材质、表演微节拍、声音和物理描述。

## 字节预算

压缩优先保留：剧情与身份 > 参考职责 > 动作/结束状态 > 表演/对白 > 摄影/灯光 > 声音 > 高风险禁止项 > 装饰风格。编译器按语义行逐项压缩并记录 `droppedFragments`，不再整段粗暴删掉；100 级锁定剧情和动作不会被压缩。必需信息仍超限时阻断，不截断剧情。

手工修改会产生 `manualOverride=true` 新版本，并重新 lint 和预检。Envelope 记录源 revisions、能力快照、降级、专家/知识 lineage、编译器版本和 payload hash。
