# 文字 → 图 → 视频 → 剪辑电影工业主路径

真正的 AI 短剧/电影不是把同一段文字分别交给图片模型和视频模型。它是一次跨模态状态传递：每一步只把下一步真正能继承、能验证的状态压进像素、合同和时间线。

## 编排边界（强制）

UnunuTV 是唯一的电影工业编排器和执行运行时。本地 Agent/Skill 只负责把
Owner 的 brief、锁定事实、已验收媒体 ID、结构化镜头数据和决策交给
UnunuTV，并消费 `status.nextAction`；不得在本地重新拆剧情、重写正式 Prompt、
造占位图、自动 ACCEPT、绕过 GenerationUnit，或直接调用 Provider。

`workflow short-drama` 和 `workflow one-shot` 只是进入
`startCinematicWorkflow → cinematic-status → nextAction → cinematic-advance`
的入口适配器，不是第二套出片管线。旧的 `produceShortDramaOnCanvas` 不属于
Agent/CLI/API 的生产路径；缺少合同、真实参考或验收证据时，UnunuTV 必须阻断并
返回缺口，而不是猜测或静默降级。

## 主链

```text
StoryProductionPacket / VisualBible
  → Shot：叙事任务、表演、轴线、站位、摄影、光、声音、剪辑出口
  → Director Stage：统一场景拓扑、世界坐标、人物/道具占位、机位
  → 按模式选择：语义参考图组，或真实首帧/首尾帧/续接尾帧
  → 故事板（可选）审批构图/调度；动态预演（按风险）审批时间/运动
  → 时空运动合同：阶段、状态轨、相邻状态过渡、速度/接触/中间态
  → Video：参考图只控制声明事实，Prompt 与运动合同驱动本段演化
  → 全时间线审片：逐相邻帧检查运动派生量并记录真实出口状态
  → 正典对账：接受事实/偏差/已完成节拍写回，拒绝候选不更新正典
  → 下一镜从最新 ACCEPT carry-forward 重新编译
  → TAIL_CONTINUE 或 DUPLICATE_HANDOFF
  → 专业时间线：删除重复区、完成动作/视线/声音匹配
  → 技术 QC、母版与交付
```

资产 Authority 决定“它是谁/空间是什么”；Director Stage 决定“它们在哪里、摄影机在哪里”；语义参考图决定“哪些静态事实必须继承”；硬帧载体只在对应模式中决定真实 `t0`/端点；时空运动合同决定两帧之间怎样演化。它们不能相互冒充。多镜头一致性来自共同 Authority/拓扑、逐镜模式合同与真实出口状态，不来自让所有镜头共用一张泛化故事板。

## 计划状态不等于银幕事实

每个生成单元在执行前把剧情拆为 `alreadyHappened / thisUnitOnly / reservedForLater`，执行后把完整时间线审片结果写成 `observedStartState / observedEndState`。只有最新 ACCEPT 的观察结果经 `canonReconciliation` 接受后，才成为下一镜的 `carryForwardState`。因此模型提前完成一个动作、少走一步、道具意外落地或角色停在计划端点之前时，系统不会假装计划已经发生；它要么接受偏差并重编下一镜，要么拒绝候选并保持原正典。

这也是长链一致性的控制点：身份与世界设计持续来自 Authority，上一段接受成片只负责短期实际状态。连续使用输出作为下一次输入会累积漂移，故每单元显式配置 `maxExtensionDepth`，到达上限或提前观察到身份/空间/动作/声音漂移就用稳定 Authority 和接受镜头重锚。固定链深仅是待实测启发，不是跨模型定理。

## 五域硬帧状态载体

进入 `first_frame` / `first_last_frame` 的真实关键帧必须由当前 Shot 产生并逐像素验证：

- `character_identity`：人物/怪物身份、服化、解剖和不可逆状态；
- `scene_topology`：门、桌、楼梯、柜台、通路、破坏状态和光源位置；
- `spatial_blocking`：每个主体的 screen zone、前后层、身体朝向、视线、手/道具和接触面；
- `camera_composition`：机位、焦段、画幅内层级、景深、焦点和运动入口；
- `continuity_state`：承接上一时刻的数量、伤势、武器、服装、群体占位和银幕方向。

证明必须绑定最新 media review、媒体 checksum 和当前 Shot revision。以后追加 REJECT 时旧 ACCEPT 立即失效，旧 compilation 变 stale。文字合同正确但像素错误，仍然不得进入视频。

若模型在 first-frame/first-last-frame 模式禁止普通参考图，就把 Authority、场景、Director 站位与镜头状态先合成并验收为这一张载体图。其他参考只保留 lineage，不能偷偷混入 Provider payload。这不是丢失知识，而是把跨模态可继承状态提前“烘焙”进像素。

## 约束预算，而不是“文生满血 / 图生阉割”

文生视频与图生视频交换的是自由度和可控性，不是简单的品质高低。必须把“一致性”拆成四项分别判断：片内时间/动作一致性、外部人物身份一致性、跨镜连续性、空间站位一致性。

- 文生视频能从一开始选择适合运动的世界并联合演化，在单条视频内部的动作、运镜、时间和局部空间连续性上可能优于硬首帧；但它的“自洽”不等于符合外部角色母版，也不保证另一条独立生成仍是同一个人/同一个空间；
- 首帧图生视频精确锁定 `t0`，却必须从一张二维静态图推断不存在的时间、速度、受力和三维遮挡信息；约束过强时会僵，运动/机位偏离时会形变或漂移；
- `image_reference` 与 `first_frame` 不是同一种带图模式。前者允许图片只提供选定语义事实、由文字替换或补全其他事实；后者要求原图成为真实第0帧，不能一边锁像素一边要求第0帧把可见错误物体改掉；
- 首尾帧再增加一个目标约束，只适合身份、拓扑、动作相位、机位、光线相容的两个端点。端点跨度过大时，模型会用形变、错误插值或隐藏切镜“还债”。

## 图文混合控制：图片不是整张真相

每张参考图进入 Provider 前必须拆成逐项职责：

- `preserve`：必须保留的人物身份、站位、拓扑或构图；
- `replace`：图中可见但必须由文字替换的错误事实，例如现代桌 → 古代客栈木桌；
- `complete`：图中缺失、画外或被遮挡而必须重建的内容，例如被遮挡区域补出更多尸体；
- `ignore`：不得继承的现代器物、错误人物、错误五官或临时遮挡；
- `styleOnly`：只借色彩、材质、光线，不借具体内容；
- `temporalRole`：这张图只负责身份、静态状态、初始状态、动作相位、端点还是续接状态。

这就是可执行的“图生解锁”：不丢掉图片，而是只锁正确事实，把错误像素、遮挡后的世界和运动控制权交还给文字。若原图含现代桌、文字要求古代桌，同时又把原图声明为实际 `first_frame`，合同自相矛盾，必须先生成修正关键帧或改用 `image_reference`。

## 静态状态与动态合同分离

图片只能证明一个时刻 `S(t0)`，不包含谁先动、人物与摄影机轨迹、加减速、动作相位、重心/接触、揭示顺序和结束状态。中高复杂运动必须另有动态合同：`subjectTrajectories / actionPhases / timing / cameraTrajectory / physicsContinuity / endState`。动作语义仍有歧义时，再增加动作相位板或经验证的运动参考。

文字时间段也仍然不等于动画。正式中高运动镜头还要有结构化 `temporalMotionPlan`：统一 fps 与总时长；从 0 秒连续覆盖到端点、无空洞/重叠且有因果依赖的阶段；每个运动人物、道具、摄影机与环境元素的状态轨；每一对相邻状态之间的路径、插值、速度曲线、动作相位、接触变化与必经中间态。生成后按相邻帧核对位置/朝向差分、速度/加速度连续、接触、动作相位和银幕方向。只抽若干“好看关键帧”不能证明动画成立。

### 故事板与动态预演不是一回事

故事板是可选的空间/叙事审批层：复杂构图、打斗站位、局部特写在完整场景中的区域、VFX 落点、覆盖镜头与切镜意图需要时才做；简单镜头不应为了流程完整而强制生成故事板。故事板仍是静态采样，不能证明相邻帧运动。

动态预演（animatic/Director previs）是时间审批层。它用代理人物、轨迹和低成本运动把阶段时长、加减速、接触时刻、摄影机与主体相对运动、遮挡接缝和剪辑节奏先跑通，再把结果固化为 `temporalMotionPlan`。因此“故事板管空间，动态预演管时间，精确 Prompt 管语义与可见事实，成片全时间线验收真实结果”。

### 所有运镜都不能只靠一句自然语言

“推进”“跟拍”“下摇”“手持”与“顺时针环绕 90 度”一样，都不是完整执行合同。它们仍然缺少观察坐标系、起终机位与视轴、路径、焦段/焦点、速度、主体相对运动、遮挡和终点构图。不同解释都可能满足短句，却产生完全不同的镜头。因此凡摄影机状态发生变化，必须绑定结构化 `cameraTrajectoryPlan`：

- 世界坐标或主体局部坐标，以及数字化起终位置、偏航/俯仰/滚转、视场角和焦点距离；
- 推/拉/跟/横移/升降/摇臂用空间路径曲线，摇镜/俯仰用视轴角度弧，变焦/拉焦用时间曲线，手持用振幅包络，复合运镜同时绑定多种控制图形；
- 环绕/弧线再增加明确轴心、从正上方观察的顺/逆时针、半径和圆弧度数；
- 时长、加速—匀速—减速曲线和 look-at；
- 构图守恒、主体相对运动、遮挡计划和背景视差预期；
- Director camera route，以及不含辅助标记的首/中/尾干净构图帧。

路径线、视轴弧、焦段/焦点曲线、手持包络、箭头、轴心点和文字有两种合法用途。`editor_only` 只在导演台显示，不进入 Provider；`provider_reference_only` 则允许把它们画在一张由干净空间母版派生的“标注控制参考图”上，但只允许用于 `image_reference`。每个圈选区域、路径和箭头必须有唯一 ID、明确含义、起止时间和动作指令；标注图与最终 Prompt 必须从同一个 `controlGeometryId` 合同生成，图上向左而文字向右、图圈 R1 而文字放大 R2、或标注时间超出镜头时长都必须阻断。Prompt 还要明确圆圈、线条、箭头和标签只是控制标记，不得成为成片物体。

带标注图绝不能成为 `first_frame`、`last_frame`、人物/场景 Authority 或干净状态载体。首帧/首尾帧像素必须无标注。内部 media、control geometry 和 capture ID 仍不得泄漏到内容 Prompt。

### 参考图、首帧与局部空间定位

`image_reference`、`first_frame`、`first_last_frame` 是互斥的 Provider 输入形态。普通分镜图默认只承担人物、场景、构图、空间关系或动作相位参考；剧情事实、主体运动、运镜和时序仍由逐镜动态 Prompt 决定。只有明确标成 `storyboard_first_frame` 且当前图片、checksum、Shot revision 和五域像素验收全部一致时，才允许把它提升为真实 `t0`。续接镜头则只允许上一段最新 ACCEPT 的真实尾帧作为硬首帧。

局部镜头还要知道“它属于完整场景的哪一块”。完整场景母版可以在规划阶段建立区域坐标，也可以派生带圈选/路径的 `image_reference` 告诉模型 R1/PATH_A 的空间含义。但若当前 Provider 的首帧模式禁止同时提交普通参考图，就必须诚实二选一：精确继承上一段尾帧，或用完整母版进行语义定位。两者都不可丢时，要先构造并验收桥接关键帧，或设计遮挡擦镜、动作重叠与剪辑交接；不能把完整母版偷偷当成上一段尾帧，也不能假装模型同时收到了两类互斥输入。

参考图可见事实与 Prompt 不得发生未声明冲突。允许修改的现代桌、临时遮挡或缺失区域必须分别写进 `replace / ignore / complete`；其余人物、场景、拓扑、区域和运镜标注必须与 Prompt 同源一致。

即使模式必须是 `first_frame`，首帧也只继承或建立 `t0` 的入口边界，并不负责冻结或规定整段视频。新镜首帧标记为 `initial_state`，从上一条已验收视频提取的尾帧标记为 `continuity_state`；从 `t0+1` 开始，人物动作、运镜、节奏、物理和出口状态全部回到独立动态合同。`first_last_frame` 同理：尾帧只是 `endpoint`，首尾之间怎么演化仍必须明确设计。

因此专业生成不是“有一张准图 + 一段泛化提示词”，而是：静态图逐项事实合同 + 独立时间演化合同 + 模式能力预检 + 全时间线四维验收。静态图不得冒充运动轨迹，尾帧不得冒充续段完整动作。

用户参考图所说的“调角度、拉景别让模型逃逸”有可用内核：强首帧约束下，主动的 orbit、dolly、push-in 或 pull-out 有时能让后半段恢复更丰富的运动。但它不是“模型从图生切回文生”的证明，而是约束与运动轨迹重新分配。它同样会放大身份漂移、透视拉伸、头身拓扑变化、轴线反转和模型自造切镜。

因此任何“解锁”必须变成可验证的 `constraint release` 方案：先说明哪些事实全段永不释放，哪一秒开始只释放构图/景别，摄影机走什么路线，动作相位和屏幕方向如何守恒，在哪里形成可剪出口；再按模型做同状态 A/B，对比文生、静态首帧、首帧＋释放、相容首尾帧四组的全时间线。验收至少覆盖身份、拓扑、站位、运动丰富度、非预期切镜、伪影和可剪性。

《血月客栈》P01A 不允许在尸傀解剖揭示阶段使用这种逃逸：唯一完整脸在后脑、头部正前方无脸、身体朝桌和桌席占位必须先被清楚证明。需要换机位时，使用已经设计的白璃斗篷全画幅擦镜 H1，把约束释放放到真实遮挡接缝之后；P01B 再从新的、已验收状态载体开始，而不是让 P01A 在无遮挡时任意旋转或拉景别。

## 15 秒上限与超长镜头

模型时长上限是分段边界，不是叙事边界。先按动作和摄影机相位设计 4–15 秒 Provider 段，再选择一种互斥交接：

### TAIL_CONTINUE

从上一条最新仍为 ACCEPT 的视频抽真实 H1/尾帧，作为下一段唯一首帧。下一段从 H1 后直接产生新动作，不复演 H0→H1。适合能在同一构图/运动状态继续的段落，也适合真实 H1 已形成全遮挡、前景 wipe、甩镜峰值、闪白、暗帧或运动模糊的隐藏拼接。

### DUPLICATE_HANDOFF

从同一条最新仍为 ACCEPT 的视频抽取不同的 H0 与 H1。下一段先复现 H0→H1，再从 H1 后明显推进；剪辑时删除下一段开头重复区。切点按实拍/生成后的重复动作、速度峰值和接触相位确定，不使用固定秒数。

已有正向实测证明：在记录的同模型/模式/时长/角色/场景/故事条件下，显式 H0→H1 重叠规则能产生更长的可编辑重复区并继续新内容。对应能力与知识原子为：

- `cap-overlap-handoff`；
- `cap-multi-video-overlap-handoff-rule`；
- `kn-069083632f33958d2288`：下一段先复现 H0→H1，再推进；
- `kn-e96ba5c04cd576e5020a`：切点没有固定通用秒数；
- `kn-f691b8cac671f335525f`：H1 后必须出现明确新内容。

证据仍为 `LIMITED`：尚未证明所有模型的自动触发隔离与互斥压力条件。不能把成功案例升级成万能 Prompt。

## 无缝的守恒与验证

每个接缝必须同时核对：人物站位、道具、光线、动作相位、银幕方向。还要记录：

- 摄影机离缝前和入缝后的运动方向、速度曲线、停点；
- 焦段、景深、焦点位置和曝光保护；
- H0/H1 的 prepare/contact/reaction/recovery 相位；
- 环境底、混响尾和一个可对齐的同步声点；
- seam opportunity、cut rule 和 trim plan。

画面“像”不能代替证明。H0/H1 必须来自同一条最新仍为 ACCEPT 的上一段；Owner 后写 REJECT 会同时撤销尾帧续接和重叠交接。没有真实帧时可以先保存方案，但预检必须保持 blocked，禁止伪造媒体 ID 或付费生成。

## 专业运镜与切镜

运镜先写叙事动机，再写机位路线。每次移动必须说明：观众现在需要看到什么、摄影机从哪里到哪里、人物如何反向或同向移动、何时加速/减速/停止、焦点何时转移、运动结束后留下什么剪辑出口。人物路径和摄影机路径必须分别记录。

切镜必须由信息、动作、视线、遮挡、闪光或声音驱动，并在时间线上检查 eye trace、动作相位、图形、方向和速度匹配。反应镜头不是装饰，它承担因果和节奏；声音桥负责跨镜保持空间。打斗按目标/战术和 prepare→contact→reaction→recovery 编排，动作源必须从命名发起者的手/武器/接触点连续到目标，coverage 同时保留接触、受力、反应和空间恢复。

“大师感”不能作为验收项。可验收的是：信息揭示准确、空间可读、动作和摄影机都有起止、相邻镜守恒、接缝可剪、声音连续，最终时间线没有靠观众脑补来修复的跳位或身份漂移。
