# UnuTV 端到端影视生产系统：Reference Director Core v1

状态：产品重置提案
日期：2026-07-27
适用范围：电影、短剧、动画和系列化 AI 视频生产

## 1. 决策摘要

UnuTV 的最终价值不是生成一个漂亮镜头，而是让创作者能够从一个创意开始，
持续完成一部真正可交付的电影，或一季多集、人物和世界观保持连续的优质短剧。

UnuTV 应收束为：

> 以 Reference Director 为镜头控制内核的端到端 AI 影视生产系统。它从项目
> 开发、剧本、资产和分镜出发，用低模预演确定场景关系、人物站位、主体运动
> 和摄影机轨迹，再组织模型生成、候选筛选、剪辑、声音、质检和交付，最终完成
> 一部电影或一季连续短剧。

Reference Director 不是 UnuTV 的全部产品，而是整条生产链中最难替代的控制
核心。它解决单个镜头的空间与运动确定性；项目、剧集、剧本、资产、生成、
剪辑和交付系统负责把许多镜头组织成一部完整作品。

因此 UnuTV 既不是“简化版 Blender”，也不是把所有 AI 工具堆在一起的大而全
工作台。它是一套以成片交付为目标、以正式生产产物连接各阶段的影视生产系统。

本次调整是产品与主工作流的重构，不是推倒现有代码重写：

- 继承 OpenMontage 的阶段化生产、能力预检、检查点和审计思路；
- 继承 Toonflow 的项目、剧集、剧本、资产、分镜和批量生产组织方式；
- 吸收 script-writing-studio 的项目开发、剧本会诊、台词、资产、导演知识和
  声音设计方法，但不以长 Prompt 作为主控制手段；
- 以 UnuTV 已有 Director Stage、摄像机、路线、关键帧和 Provider
  能力系统作为核心实现基础；
- 把“动态参考视频”提升为从数据合同到 Provider Payload 的一等对象；
- 让剧本、资产、镜头、候选、剪辑、声音和交付共享同一份可追踪生产状态。

## 2. 产品为什么要重置

### 2.1 当前问题

当前 UnuTV 同时呈现了太多概念：

- 剧情、资产权威、故事板、生成单元和复杂审查合同；
- 节点画布、3D 世界、全景、Gaussian Splat 和导演台；
- 人物关节角度、姿态、摄影机、路径和动画轨道；
- 多个模型、参考模式、时间线、后期和交付。

这些能力并非没有价值，但主次不清。用户无法快速回答：

1. 当前在做哪一集、哪一个镜头？
2. 这个镜头的空间和运动是否已经确定？
3. 现在提交给模型的参考到底控制什么？
4. 模型失败后应该改资产、改镜头，还是继续抽卡？

### 2.2 重置后的核心问题

UnuTV 最终必须回答：

> 如何把故事、剧本、角色资产、导演意图和模型生成组织成可持续、可审查、
> 可恢复的生产流程，稳定完成一部电影或一季多集短剧？

其中最先要打穿的关键瓶颈是：

> 在付费调用视频模型之前，把一个镜头的空间、人物走位、摄影机运动和时间
> 节奏先跑通，并输出模型可消费的动态控制包。

所以“单镜头 Reference Director”是 v1 的实施切口，不是产品终点。任何阶段性
收缩都必须服务于端到端成片，不能把 UnuTV 永久缩成只能制作孤立镜头的工具。

### 2.3 低模的含义

低模不是廉价视觉风格，而是一种控制媒介：

- 不追求人物外观精度；
- 不制作细致表情和复杂骨骼动画；
- 不承担最终材质、灯光和渲染；
- 只保留理解镜头所必需的空间、运动、遮挡、节奏和构图信息。

最终人物外观由资产包控制，成片质感由 AI 视频模型完成。

### 2.4 成片而不是片段

产品成功不能以“生成了多少视频片段”衡量。正式产物必须能够进入上一层或下一层：

- 创意进入项目档案和故事圣经；
- 大纲进入剧本和集级结构；
- 剧本进入资产需求和镜头计划；
- 镜头计划进入 Director 与生成单元；
- 接受候选进入剪辑时间线；
- 剪辑进入声音、字幕、调色和质检；
- 通过质检的版本进入整集、整片和发布交付。

没有进入成片时间线的孤立生成结果只能视为候选素材，不能视为完成。

## 3. 参考产品结论

### 3.1 OpenMontage：借生产操作系统，不借复杂前台

值得继承：

- 所有生产进入明确 Pipeline；
- 每个阶段产生正式、可验证、可版本化的产物；
- 生成前检查真实模型能力；
- 付费生成前显示供应商、模型、成本和执行方式；
- 状态、决策、生成活动和花费从同一份生产数据派生；
- 接受、拒绝和改版保留历史，不静默覆盖。

不直接照搬：

- 面向开发者的 Skill/Manifest/工具注册细节；
- 过多的前台审批点；
- 将用户暴露在每个内部生产阶段；
- OpenMontage 的代码。其仓库为 AGPLv3，未经开源策略评估不直接复制。

对 UnuTV 的落地：

- 后台保持严格状态机；
- 用户侧仅暴露三个关键门：
  1. 镜头清单确认；
  2. 动态预演确认；
  3. AI 成片候选确认。

### 3.2 Toonflow：借内容组织，不借无限画布主界面

值得继承：

- `项目 → 剧集 → 剧本 → 资产 → 分镜 → 生成` 的信息层次；
- 角色、场景、道具和音频作为可复用资产；
- 分镜表是批量生产的结构化入口；
- 多个分镜可组合成一个 Provider Track；
- 模型能力决定参考素材类型与数量；
- 生成结果保留历史版本。

不直接照搬：

- 把无限画布作为默认生产入口；
- 依靠长篇模型提示词代替真实运动控制；
- 让脚本 Agent、生产 Agent、资产面板和生成面板形成多个相互竞争的状态；
- 仅在类型或界面上声明参考视频，而正式工作台链路又将视频降级为图片。

对 UnuTV 的落地：

- 镜头列表是默认主视图；
- 无限画布保留为高级“生产关系视图”；
- 每个镜头在独立 Director 中设计；
- 模型输入包由系统编译，不让用户手工维护引用编号和冗长提示词。

### 3.3 script-writing-studio V2.0：借导演知识，不借长 Prompt 主链

本次审计对象是“导演内部专用 Skill V2.0 测试版”中的
`script-writing-studio`。该 Skill 通过了 Codex Skill 结构校验，主入口
262 行，包含 35 个参考模块、约 13,337 行 Markdown 规则和一份 16 页使用
手册。

其本质是一个端到端中文创作总控：

```text
项目开发
→ 平台节奏档案
→ 完整剧本
→ 剧本会诊与改稿
→ 台词精修
→ 资产库
→ AI 视频文字分镜
→ Seedance 提示词
→ 后期音乐与声音设计
```

值得继承：

- 阶段路由和正式交接物；
- 剧本会诊、台词指纹和平台节奏判断；
- 人物、场景、道具、服装、妆发、风格和连续性资产的分类意识；
- 摄影机行为锁：位置、距离、高度、方向、速度、稳定程度、起止状态和禁止项；
- 动作戏的“起手 → 接触点 → 受力结果 → 反应 → 段末状态”物理链；
- 首帧、场景多角度、调度图、人群和道具单实例等风险意识；
- 将 Provider 生成限制集中在适配阶段，而不是散落到每次创作对话中。

不直接照搬：

- 以 11 个文字字段或压缩导演轨作为最终镜头控制载体；
- 依靠 1,900–2,000 字提示词描述摄影机路径和人物相对运动；
- 让用户手工维护 `@图N`、`@图片N`、`@视频N` 等上传编号；
- 将 Seedance 的 4–15 秒、单组最多 9 张图片等限制反向固化到上游创作合同；
- 将 A/B/C 提示词模式暴露为用户需要理解的产品概念；
- 把编剧、导演、资产、模型适配和后期声音包装成一个不可拆分的产品模块。

对 UnuTV 的落地：

- 将 01/01b/02/03 建成一等上游 Story Director 能力，但与镜头执行状态解耦；
- 将 05 的资产知识编译成强类型资产绑定，而不是人工图号表；
- 将 04/04b 改造成 `Shot Intent` 与 Director 预设编译器；
- 将 06 降为 Provider Adapter；模型支持参考视频时使用“动态参考＋外观资产＋
  短 Prompt”，不支持时才编译长 Prompt 或静态阶段帧降级包；
- 将 07 保留为候选生成后的独立声音设计阶段。

该包包含固定版权、官网和微信推广声明，并以付费 Skill/指导服务形式分发。
在授权范围未确认前，只研究其工作方法和抽象，不直接复制规则正文、删除署名
或将原包并入 UnuTV。

## 4. 产品原则

### 4.1 一镜一控制闭环

每个镜头必须独立完成：

```text
镜头意图
→ 资产绑定
→ 低模布景与站位
→ 人物/摄影机轨迹
→ 连续预演
→ Owner 接受
→ 模型输入包
→ 候选生成与比较
→ 成片接受
```

### 4.2 三种职责不能混淆

| 输入 | 负责内容 | 不负责内容 |
|---|---|---|
| 资产包 | 人物身份、服装、场景外观、道具外观 | 镜头运动与动作时间 |
| 动态参考视频 | 空间关系、人物走位、摄影机轨迹、遮挡与节奏 | 最终外观质量 |
| 意图提示词 | 情绪、表演语义、物理细节、声音、必须保持或允许变化的事实 | 用长文本替代可视化运动 |

### 4.3 先控制，后生成

未接受动态预演的中高运动镜头不得进入正式付费生成。简单静止镜头可以按风险
跳过动态预演，但必须记录跳过理由。

### 4.4 界面简单，内部合同严格

用户看到的是“镜头是否准备好”。内部仍可以维护：

- Story/Shot revision；
- 资产权威；
- 时间运动合同；
- 摄影机轨迹；
- 模型能力快照；
- Provider Payload；
- Owner 接受记录；
- 生成和评价证据。

这些合同不应全部变成默认表单。

### 4.5 不静默降级

如果用户选择“动态参考视频控制”，但当前模型不支持参考视频，系统必须明确：

- 当前模型不支持哪一种输入；
- 将自动退化为什么组合；
- 哪些控制会变弱；
- 是否需要改用其他模型。

不得把视频文件静默当作图片、首帧或普通素材提交。

### 4.6 导演知识与镜头执行分层

UnuTV 必须明确区分：

```text
故事与导演知识
→ 结构化 Shot Intent
→ 可播放的 Director 控制
→ Provider 输入包
```

- 导演知识负责判断“为什么这样拍”和“需要控制什么”；
- `Shot Intent` 保存叙事、动作、空间、摄影和连续性语义；
- Director Stage 负责把意图变成可见、可编辑、可播放的运动；
- Provider Adapter 负责根据当前模型能力选择参考视频、外观资产、阶段帧和
  Prompt；
- 任何 Provider 的字数、时长、参考数量和字段格式都不得成为
  `Shot Intent` 的核心结构。

### 4.7 作品是最高层生产单元

镜头是控制单元，场景是拍摄组织单元，集是短剧交付单元，电影或一季短剧才是
最终作品单元。

所有局部状态必须能向上汇总：

- 镜头是否具备剧本依据、资产绑定、预演接受和成片接受；
- 场景是否覆盖剧本要求，空间、服装、道具和光线是否连续；
- 单集是否结构完整、节奏成立、对白完整、声音和字幕齐备；
- 跨集人物状态、关系、服装、伤势、关键道具和世界规则是否延续；
- 整部作品是否通过叙事、画面、声音、技术和发布规格质检。

任何功能都应回答它如何提高整集或整片的完成率、质量、一致性或生产效率。

### 4.8 质量不能被自动化替代

端到端不等于一键生成。系统可以自动规划、检查、编译和生成，但以下关键决策
必须保留创作者接受状态：

1. 项目方向与故事圣经；
2. 定稿剧本；
3. 角色、场景和视觉风格资产；
4. 关键镜头与动态预演；
5. AI 成片候选；
6. 场景剪辑和整集/整片锁定；
7. 最终声音、字幕与交付母版。

低风险批量任务可以自动执行，高影响创作决策必须可比较、可退回、可版本化。

## 5. 信息架构

### 5.1 顶层

```text
项目库
└── 项目
    ├── 项目圣经
    │   ├── 题材、主题与受众
    │   ├── 世界观与视觉规则
    │   └── 人物关系与长期弧光
    ├── 电影 / 季
    │   └── 集
    │       ├── 剧本
    │       ├── 场景
    │       ├── 镜头
    │       ├── 生成
    │       ├── 剪辑
    │       ├── 声音与字幕
    │       └── 集级质检
    ├── 共享资产
    ├── 连续性台账
    ├── 作品时间线
    └── 母版与交付
```

### 5.2 项目页

项目页回答：

- 正在制作哪一部电影、哪一季、哪一集；
- 故事、剧本、资产、镜头、剪辑、声音和交付分别处于什么状态；
- 全片/全季共多少场、多少镜头；
- 多少镜头未设计；
- 多少镜头预演已接受；
- 多少镜头正在生成；
- 多少镜头已有可接受成片；
- 多少场景已剪辑锁定；
- 哪些集存在连续性、缺镜、缺声音或质检阻断；
- 当前累计生成成本和平均重试次数。

### 5.3 镜头列表

每条镜头显示：

- 镜头序号和标题；
- 时长；
- 场景；
- 出场人物；
- 景别和简短叙事任务；
- 资产完整度；
- Director 状态；
- 动态预演状态；
- 模型候选状态；
- 已接受版本。

默认按叙事顺序排列。支持按状态筛选，但不以自由拖拽画布作为主要导航。

### 5.4 端到端生产主链

```text
01 项目开发与故事圣经
→ 02 电影结构 / 季与分集规划
→ 03 完整剧本与剧本会诊
→ 04 资产圣经与连续性基线
→ 05 场景拆解与镜头计划
→ 06 Shot Intent
→ 07 Reference Director 动态预演
→ 08 Provider 生成与候选接受
→ 09 场景剪辑与整集/整片装配
→ 10 音乐、对白、音效、字幕与调色
→ 11 叙事、连续性和技术质检
→ 12 母版、版本与发布交付
```

每个阶段都必须具有：

- 明确输入；
- 正式输出；
- 版本和来源；
- 完成条件；
- 阻断原因；
- Owner 接受状态；
- 可回退的上一版本；
- 对下游的可机读交接。

### 5.5 电影与多集短剧的差异

| 维度 | 电影 | 多集短剧 |
|---|---|---|
| 最高结构 | 幕、序列、场景 | 季、集、段落、场景 |
| 节奏控制 | 全片弧线和序列推进 | 单集钩子、留存点、集尾悬念 |
| 连续性 | 全片时间、人物和视觉连续 | 跨集状态、复用资产和长期人物弧 |
| 生产排程 | 按场景、地点、资产聚合 | 按集交付，同时复用共享资产 |
| 质检 | 全片叙事、视听和技术母版 | 单集质检＋全季连续性质检 |
| 版本 | 导演版、剪辑版、发行版 | 每集版本＋整季版本 |

底层镜头和资产合同共用，上层结构、节奏闸门、排程和交付模板分别配置。

## 6. Director 镜头控制台

### 6.1 页面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 镜头信息 / 当前机位 / 画幅 / 保存 / 生成动态参考视频         │
├──────────────┬─────────────────────────────┬─────────────────┤
│ 场景与人物   │ 2.5D俯视 / 编辑视角 / POV   │ 镜头属性        │
│ 镜头列表     │                             │ 运镜与跟随      │
│ 资产绑定     │          低模舞台           │ 起幅/落幅       │
│              │                             │ 速度曲线        │
├──────────────┴─────────────────────────────┴─────────────────┤
│ 播放 / 时间 / 人物轨 / 摄影机轨 / 关键节点 / 速度曲线       │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 P0 功能

#### 场景

- 添加、删除、移动、旋转、缩放场景元素；
- 使用基础几何体、低模人物和代理道具；
- 绑定资产身份，但不要求低模外观接近最终人物；
- 显示人物与道具的名称；
- 支持对象锁定、显示与隐藏。

#### 人物

- 站位；
- 朝向；
- 简单路径；
- 站立、行走、奔跑、坐下、蹲下等少量动作预设；
- 起点、必经点、终点；
- 到达时间；
- 是否保持面向目标。

P0 默认不暴露逐关节编辑。关节数据可继续存在于兼容层或高级模式。

#### 摄影机

- 摄影机位置；
- 注视目标；
- FOV/焦距近似；
- 画幅比例；
- 起幅和落幅；
- 多个运镜节点；
- 主体跟随；
- 构图保持；
- 第一视角预览。

#### 运镜预设

- 固定；
- 推近；
- 拉远；
- 横移；
- 升降；
- 跟拍；
- 左弧线；
- 右弧线；
- 环绕；
- 复合路径。

弧线运镜必须记录：

- 轴心；
- 左/右方向；
- 半径；
- 起始角；
- 结束角；
- 注视对象；
- 时长；
- 速度曲线。

#### 时间与速度

- 总时长；
- 多关键节点；
- 节点到达时间；
- 匀速；
- 缓入缓出；
- 加速；
- 减速；
- 自定义速度点；
- 人物轨和摄影机轨同时播放。

#### 视图

- 2.5D 俯视：默认布景和画路线；
- 自由编辑：调整高度和遮挡；
- 摄影机 POV：检查真实构图；
- 起幅/落幅并排比较；
- 连续播放。

### 6.3 P0 不做

- 精细人物建模；
- 材质和毛发；
- 面部表情制作；
- 复杂骨骼动画；
- 布料、流体、破碎等物理模拟；
- 专业灯光和离线渲染；
- Blender 文件格式兼容；
- 完整非线性剪辑器；
- 把 Gaussian Splat 或全景环境设置成必须步骤。

### 6.4 `Shot Intent` 与导演知识编译

每个镜头在进入 Director 前应有一份轻量、可版本化的 `Shot Intent`。它不是
完整提示词，也不是必须全部手填的表单，而是由剧本、资产和导演助手共同产生，
再由用户通过镜头控制台修正。

至少包含：

```text
Shot Intent
├── 叙事功能
├── 主体、对象与资产绑定
├── 起始空间关系
├── 目标结束状态
├── 动作阶段与物理结果
├── 摄影机意图
├── 焦点与主体跟随
├── 节奏、时长与速度倾向
├── 光影、表演与声音意图
├── Must Keep
├── Avoid
└── 连续性与下一镜交接
```

导演知识库不应只输出自然语言句子，而应优先编译为可执行预设：

| 导演知识 | Director 参数 |
|---|---|
| 固定镜头 | 机位、注视目标、稳定锁、禁止漂移 |
| 侧跟/背跟 | 主体、相对方位、距离、同步速度、轴线锁 |
| 缓推/后撤 | 起止距离、速度曲线、焦点目标、停止条件 |
| 左右弧线/半环绕 | 轴心、方向、半径、角度、时长、注视对象 |
| 手持微动 | 跟随目标、微动幅度、频率、允许偏差 |
| rack focus | 前后景焦点对象、切换时间和相机是否固定 |
| 动作戏物理链 | 起手、接触点、受力结果、反应、段末位置 |

自然语言仍可作为预设说明和 Provider 降级输入，但不得成为唯一执行载体。

## 7. 动态参考控制包

### 7.1 标准输出

每个已接受镜头输出：

```text
shot-control/
├── reference-preview.mp4
├── start-frame.png
├── end-frame.png
├── phase-frames/
│   ├── phase-01.png
│   └── phase-02.png
├── shot-intent.json
├── shot-control.json
├── appearance-references/
└── model-prompt.txt
```

`shot-intent.json` 保存与 Provider 无关的叙事、表演、空间、摄影和连续性语义；
`shot-control.json` 保存已被 Director 接受的可执行轨迹。两者分别版本化，避免
改 Prompt 时意外覆盖已接受的镜头运动。

### 7.2 `shot-control.json`

至少包含：

```json
{
  "version": "unutv_shot_control_v1",
  "shotId": "shot-001",
  "shotRevision": 1,
  "durationSeconds": 8,
  "frameRate": 24,
  "aspectRatio": "16:9",
  "cameraTrack": {
    "lookAtTargetId": "character-a",
    "followTargetId": "character-a",
    "interpolation": "ease",
    "keyframes": []
  },
  "subjectTracks": [],
  "startFrameMediaId": "",
  "endFrameMediaId": "",
  "referenceVideoMediaId": "",
  "ownerReview": {
    "state": "accepted",
    "reviewedRevision": 1
  }
}
```

正式结构应通过 `packages/contracts` 定义和校验，不能只作为 UI 私有 JSON。

### 7.3 预演渲染要求

- 输出真实连续 MP4，而不是计时切换静态图；
- 画面不得包含路径线、控制点、文字标签或编辑辅助标记；
- 代理人物可以保持低模和纯色；
- 画幅、时长、fps 与目标 GenerationUnit 一致；
- 起幅和落幅必须从同一次预演渲染中提取；
- 保存渲染时使用的 Stage revision 和媒体 checksum；
- 预演被修改后，旧 Owner ACCEPT 自动失效。

## 8. 模型能力与生成编译

### 8.1 新增一等模式

在模型能力注册中新增：

```text
video_reference
```

并分别声明：

- 最大参考视频数量；
- 参考视频最长时长和大小；
- 是否支持与普通参考图混用；
- 是否支持与首帧/首尾帧混用；
- 是否支持参考音频；
- 支持的分辨率和画幅；
- Provider 实际 Payload role；
- 最近验证时间和证据。

### 8.2 模型输入路由

| 模型能力 | 提交方式 |
|---|---|
| 支持参考视频＋图片 | 动态参考视频＋外观资产＋简短提示词 |
| 只支持参考视频 | 动态参考视频＋必要文字身份约束 |
| 不支持参考视频但支持多图 | 起幅＋动作阶段帧＋落幅 |
| 只支持首尾帧 | 起幅＋落幅＋轨迹编译提示词 |
| 只支持首帧 | 起幅＋轨迹编译提示词 |
| 仅文生视频 | 由控制包编译运动提示词，并明确控制力下降 |

### 8.3 Payload 类型

Reference Binding 必须明确：

```text
reference_image
reference_video
reference_audio
first_frame
last_frame
```

媒体 MIME、角色、数量和能力预检必须贯穿：

```text
Web
→ API contract
→ Core use case
→ model capability preflight
→ provider adapter
→ final payload evidence
```

任何一层都不得根据“不是音频”推断为图片。

### 8.4 Prompt 收缩

最终提示词只保留：

- 叙事意图；
- 人物动作语义；
- 情绪和表演；
- 物理与声音要求；
- 必须保持的外观事实；
- 允许模型丰富的细节；
- 不得出现的内容。

摄影机路径、速度和主体相对运动应由动态参考视频和
`shot-control.json` 同源编译，不继续依赖长篇自然语言重复描述。

### 8.5 Provider 约束隔离

Provider Adapter 可以维护以下限制，但不得把它们写入上游核心合同：

- 单次生成允许的时长；
- 图片、视频和音频参考数量；
- Prompt 字数或 token 上限；
- 素材上传编号和引用语法；
- 首帧、首尾帧、参考视频或视频延长的具体 Payload role；
- 模型专用的 A/B/C 模式或字段模板。

用户在资产面板绑定的是“角色、场景、道具、外观、声音和动态参考”的语义角色。
系统在提交前才把这些绑定编译成当前 Provider 的 `@图片N`、`@视频N` 或其他
协议格式。模型切换后应重新编译，不要求用户重新维护编号。

静态连续性载体的职责调整为：

| 载体 | UnuTV 中的职责 |
|---|---|
| 场景多角度图 | 场景外观与结构参考 |
| MAP/SB 调度图 | 内部辅助视图或不支持参考视频时的降级输入 |
| FF 起幅图 | 首帧模型和静态降级路线 |
| 动作阶段帧 | 不支持参考视频时补充关键动作阶段 |
| 动态参考视频 | 中高运动镜头的主要空间、调度、运镜和节奏载体 |

## 9. 候选比较与成片接受

### 9.1 样片优先

- 默认每镜先生成一个候选；
- 候选未接受前不自动批量追加；
- 批量模式属于明确操作，不作为默认行为。

### 9.2 比较界面

同屏展示：

- 动态参考视频；
- 候选 A/B；
- 起幅对齐；
- 落幅对齐；
- 人物身份；
- 空间站位；
- 主体运动；
- 摄影机运动；
- 非预期切镜；
- 可剪出口。

### 9.3 反馈分类

拒绝候选时只允许归因到：

- 资产问题；
- Director 控制问题；
- 模型遵循问题；
- Prompt 语义问题；
- Provider 技术失败。

不同归因回到不同层修复，避免所有失败都进入“重生成”。

### 9.4 候选进入作品时间线

单镜头候选只有满足以下条件才可进入正式作品时间线：

- 对应当前有效的剧本、资产、Shot Intent 和预演 revision；
- Owner 明确接受；
- 入点和出点可用于当前剪辑；
- 人物身份、空间、动作方向和关键道具通过镜头级检查；
- 媒体规格可用于项目时间线；
- 保存生成模型、输入包、成本和接受证据。

时间线引用接受版本，不复制成失去来源的新文件。候选被替换时，旧版本保留并可
回退；上游剧本、资产或预演发生实质变更时，系统标记相关时间线镜头需要复核。

## 10. 成片装配、声音、质检与交付

### 10.1 场景与作品时间线

作品时间线不是孤立的视频编辑器，而是所有已接受镜头的正式装配层：

- 按剧本场景、叙事顺序和时间码组织镜头；
- 支持镜头入点、出点、速度、转场和临时占位；
- 显示缺镜、重复镜头、时长缺口和未接受素材；
- 允许场景级和整集/整片级版本；
- 从时间线反查剧本段落、Shot、资产、生成记录和评价证据；
- 场景锁定后，上游变更必须产生影响提示，不静默替换。

P0 不追求替代专业 NLE，但必须具备完成粗剪、场景装配和可交付时间线所需的最小
能力，并支持导出到专业后期工具。

### 10.2 声音、对白、音乐与字幕

声音是正式生产阶段，不是最后附加的 Prompt：

- 保留现场对白、AI 对白、旁白、环境声、动作音效和音乐的独立轨道；
- 台词版本与剧本、说话人和口型镜头关联；
- 支持静默点、音乐进入/退出点、音效事件和声音透视；
- 自动检查漏台词、重复台词、响度异常和声画错位；
- 字幕从定稿台词和最终剪辑时间码生成，支持人工校正；
- 音乐和声音设计必须服务整场和整集情绪，不按孤立镜头各自生成。

### 10.3 电影与多集短剧连续性台账

连续性台账至少跟踪：

- 人物年龄、发型、妆容、服装和身体状态；
- 人物关系、知情状态、情绪余波和长期弧光；
- 场景时间、天气、光线、空间结构和可见损坏；
- 关键道具的持有者、位置、数量和损坏状态；
- 上一场/上一集结束状态与下一场/下一集开始状态；
- 已建立的世界规则、能力规则和禁止破坏的事实；
- 资产版本何时生效，以及影响哪些场、镜头和已生成素材。

系统应在剧本拆解、资产绑定、Shot Intent、候选接受和整集质检阶段重复检查这些
状态，而不是依靠创作者记忆。

### 10.4 多层质量闸门

| 层级 | 主要检查 |
|---|---|
| 剧本 | 因果、人物动机、结构、节奏、台词和可拍性 |
| 资产 | 身份、风格、场景、服装、道具和版本完整度 |
| 镜头 | 空间、轴线、构图、动作、运镜、连续性和可剪性 |
| 场景剪辑 | 信息覆盖、表演连续、节奏、视线和声音衔接 |
| 单集/全片 | 叙事完整、人物弧、视听统一、缺镜和重复信息 |
| 技术 | 分辨率、帧率、色彩、响度、字幕、安全区和文件完整性 |
| 发布 | 平台规格、片头片尾、版权素材、交付包和版本标识 |

AI 可以给出诊断和建议，但“质量通过”必须对应明确证据和 Owner 接受，不以模型
自评分替代审片。

### 10.5 母版与交付包

每部电影或每集短剧至少输出：

```text
delivery/
├── picture-master/
├── audio-master/
├── subtitles/
├── thumbnails-and-promo/
├── project-manifest.json
├── rights-and-source-report/
├── quality-control-report/
└── archive/
```

`project-manifest.json` 记录作品、集、时间线版本、资产版本、模型生成来源、最终
媒体 checksum 和交付规格。发布版、审片版、无字幕版、国际版等必须来源清楚，
不能靠覆盖文件名管理。

## 11. 现有模块去留

### 11.1 保留并提升

| 现有能力 | 决策 |

| 现有能力 | 决策 |

- 未被真实镜头闭环验证的模型抽象；
- 不能改善作品完成率、质量、连续性、周期或成本的功能。

### 11.4 需要新增

- 2.5D 俯视视图；
- Director 实时插值播放；
- 左/右弧线运镜工具；
- 主体跟随；
- 可视化速度曲线；
- 干净预演 MP4 渲染；
- 自动抽取起幅、落幅和阶段帧；
- `video_reference` 能力合同；
- 参考视频 Provider Payload；
- 动态参考与候选并排比较；
- `Shot Intent` 合同和版本；
- 摄影机行为、动作物理链和连续性风险预设；
- 语义资产绑定到 Provider 素材编号的自动编译；
- 场景和作品时间线；
- 跨场、跨集连续性台账；
- 声音、字幕和集级/片级质检；
- 母版、发布版本和交付清单；
- 镜头级指标与重生成原因。

## 12. 实施阶段

### Phase 0：收束界面

目标：让现有能力形成可理解的镜头产品。

- 新建镜头列表主入口；
- Director 改为单镜头工作空间；
- 为镜头建立轻量 `Shot Intent`，不要求用户填写完整 11 字段；
- 默认隐藏关节、全景、Gaussian 和合同 JSON；
- 保留编辑视角和机位视角；
- 增加 2.5D 俯视切换；
- 明确起幅、落幅、播放和“生成动态参考”主按钮。

退出条件：

- 新用户可以在不理解 Blender、节点或 Provider 的情况下建立一个镜头；
- 能清楚看到该镜头是否已完成预演。

### Phase 1：真实动态预演

目标：从静态构图工具变成连续运动工具。

- 对人物和摄影机关键帧做实时插值；
- 支持路径节点时间；
- 支持基础速度曲线；
- 支持主体跟随；
- 支持左右弧线和环绕；
- 将固定、跟拍、推拉、环绕、手持微动等导演知识编译成参数预设；
- 支持动作的起手、接触、受力、反应和段末状态节点；
- 播放时在 2.5D 和 POV 中同步更新；
- 导出干净 MP4；
- 从 MP4 抽取起幅、落幅和阶段帧。

退出条件：

- 一个 4–15 秒镜头可连续播放；
- 导出的 MP4 与编辑器预览在位置、时长、轨迹和画幅上相符；
- MP4 中没有辅助标记。

### Phase 2：动态参考模型链路

目标：完成真正的生成闭环。

- 新增 `video_reference` 模型能力；
- 新增参考视频 Binding 和预检；
- Ark/其他 Provider 按真实能力映射；
- 保存最终 Payload 证据；
- 模型不支持时明确显示退化路径；
- 自动把语义资产绑定编译为 Provider 素材编号；
- 隔离 Provider 的时长、参考数量和 Prompt 上限；
- 建立动态参考＋外观资产＋短 Prompt 的生成模板。

退出条件：

- 媒体类型从 UI 到 Provider 不发生降级；
- 用户可以确认模型究竟收到了哪些文件；
- 不支持的组合会在付费提交前阻断。

### Phase 3：候选评价与生产化

目标：证明动态参考确实减少抽卡。

- 动态参考与候选并排；
- 镜头级接受/拒绝；
- 失败原因结构化；
- 支持候选 A/B；
- 接受版本进入时间线；
- 项目页汇总重试次数、成本和通过率。

退出条件：

- 能比较静态分镜路线和动态参考路线；
- 能计算每个接受镜头的真实成本。

### Phase 4：成片装配

目标：从“能生成合格镜头”进入“能完成一场、一集或一部作品”。

- 建立场景和作品时间线；
- 接受镜头自动进入待装配池；
- 支持粗剪、占位、缺镜检查和场景锁定；
- 建立对白、环境声、音效、音乐和字幕轨；
- 建立跨场、跨集连续性台账；
- 建立场景、单集/全片和技术质检；
- 输出母版、字幕、声音、项目清单和归档包；
- 支持向专业 NLE、声音和调色流程交接。

退出条件：

- 可以从项目档案开始完成至少一集真实短剧或一部完整短片；
- 每个成片镜头均可追溯到剧本、资产、预演、Provider 输入和接受记录；
- 能发现缺镜、连续性断裂、漏声音、字幕错误和交付规格问题；
- 修改某个上游产物时，系统能指出受影响的下游镜头、场景和交付版本。

## 13. P0 验证实验

### 13.1 实验设计

选择三类镜头：

1. 简单推近＋人物静止；
2. 人物行走＋摄影机跟拍；
3. 人物移动＋摄影机弧线环绕。

每类使用相同资产、时长、模型和叙事意图，分别测试：

- A：静态分镜／首帧＋长 Prompt；
- B：动态参考视频＋资产参考＋短 Prompt。

每组至少生成足够候选，记录真实失败原因，不只挑最佳样片。

### 13.2 核心指标

镜头控制指标：

- 首次生成可接受率；
- 每镜平均重生成次数；
- 每个接受成片秒的模型成本；
- 从建立镜头到接受成片的时间；
- 摄影机轨迹遵循率；
- 人物站位与运动方向遵循率；
- 非预期切镜率；
- 身份和场景漂移率。

作品生产指标：

- 定稿剧本到可交付成片的总周期；
- 已接受成片时长占剧本目标时长的比例；
- 场景和单集一次审片通过率；
- 每分钟最终成片的生成、人工和时间成本；
- 跨镜头、跨场和跨集连续性缺陷数；
- 因缺资产、缺镜头、声音、字幕或技术规格造成的阻断时间；
- 已完成并通过质检的电影、短片或短剧集数；
- 修改上游内容后需要人工寻找和返工的下游项数量。

### 13.3 成功标准

P0 不以“有功能”判断成功，而以动态参考路线是否显著改善以下至少两项判断：

- 首次可接受率；
- 重生成次数；
- 单个接受镜头成本；
- 镜头完成时间。

若没有改善，应首先检查 Provider 是否真实接收并理解参考视频，而不是继续扩展
Director 功能。

### 13.4 端到端试产

镜头级实验通过后，必须用真实项目验证完整生产链，而不是继续制作演示镜头。

第一阶段试产选择：

- 一部 3–10 分钟完整短片；或
- 一部 3 集短剧，每集 1–3 分钟，包含稳定复用的主要人物和场景。

试产必须从项目开发开始，完整经过剧本定稿、资产基线、镜头规划、动态预演、
模型生成、候选接受、剪辑、声音、字幕、质检和母版交付。不得用外部已完成的
剧本、剪辑或声音掩盖系统断点。

试产退出条件：

- 作品从第一条项目记录到最终母版全链路可追溯；
- 没有依靠散落在聊天记录或个人记忆中的关键生产状态；
- 可以暂停并在之后从明确状态继续；
- 可以替换一个资产或重做一个镜头，而不破坏无关的已完成工作；
- 最终交付物在叙事、视听和技术上达到人工审片可接受；
- 完成第二集时，主要人物、场景和世界规则能够复用，而不是重新搭建项目。

## 14. 产品文案

### 一句话

> 从故事到成片，先把每个镜头跑通，再让 AI 把整部作品拍出来。

### 产品说明

> UnuTV 是以 Reference Director 为镜头控制内核的端到端 AI 影视生产系统。
> 它把项目开发、剧本、资产、分镜、低模预演、模型生成、候选筛选、剪辑、
> 声音、字幕、质检和交付连接成一条可追踪的生产链，帮助创作者完成一部电影
> 或一季连续短剧，而不只是生成一批彼此无关的视频片段。

### Reference Director 子产品说明

> Reference Director 用简单场景、人物站位和摄影机路径确定镜头结构，生成
> 动态参考视频，再交给 AI 视频模型完成最终外观与表演，从而减少反复抽卡。

### 不应使用的定位

- AI Blender；
- 全功能 3D 软件；
- 万能视频节点画布；
- 一句话自动拍电影；
- 纯 Prompt 工作流。

## 15. 立即生效的产品决策

1. UnuTV 的默认主入口从节点画布转为项目/剧集/镜头列表。
2. Director Stage 成为单镜头核心工作空间。
3. 动态参考视频成为中高运动镜头的正式产物。
4. 资产包继续保留，专门控制最终外观。
5. 故事板降为可选的空间审批和退化载体。
6. 人物精细关节、全景和 Gaussian Splat 默认隐藏。
7. 新功能必须能提高作品完成率和质量，或降低成片周期、连续性缺陷与真实成本。
8. 在参考视频端到端链路完成前，暂停扩展无关的节点和合同。
9. 引入 `Shot Intent` 作为导演知识与可执行预演之间的正式边界。
10. 摄影机行为和动作规则优先编译成 Director 参数预设，不以长 Prompt 为主要
    产物。
11. Provider 的时长、素材数量、编号语法和 Prompt 限制只能存在于适配层。
12. 商业 Skill 只作为方法研究来源；授权边界确认前不复制正文或并入产品。
13. 作品而不是视频片段是最高价值单位；孤立候选没有进入正式时间线就不算完成。
14. 剪辑、声音、字幕、连续性质检和母版交付属于主流程，不是外围附加功能。
15. 电影和多集短剧共用底层资产、镜头和生成合同，但分别配置结构、节奏、连续性
    和交付模板。
